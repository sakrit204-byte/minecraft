SakritCraft

A survival and crafting game with Minecraft's rules and Skyrim's world. The terrain is a continuous signed-distance field, not a grid of cubes, so every tunnel you dig has a real slope and every cliff has a real overhang. Built from scratch in C# on Vulkan.

Why this matters for the design

Ray query being available changes the lighting plan from "fake it well" to "trace it cheaply". Mesh shaders change the terrain renderer from "CPU builds draw lists" to "GPU culls its own clusters". Both are assumed throughout §08. The integrated GPU with no RT cores is why every ray-traced feature is specified with a rasterised twin.

The one thing not yet verified

Rigid-body physics needs a solver. The recommendation is BepuPhysics 2, which is pure C# with no native dependency, so it slots into the build with zero friction. That package has not yet been restored and tested here. It gets proven in M2 before anything depends on it.

01

Five pillars

When a decision is genuinely close, these break the tie. They are listed in priority order, so pillar one wins over pillar four.

1. Continuous, not cubic

The ground is a scalar field sampled in space, not a lattice of blocks. A pickaxe removes a rounded volume of rock. A cliff can overhang. A cave can be a smooth tube that narrows. Nothing in the terrain system is allowed to reintroduce a visible cube, and no gameplay rule may assume an axis-aligned unit cell.

2. Minecraft's rules, Skyrim's world

The systems that make Minecraft work are kept almost intact in their logic: darkness spawns monsters, tools have tiers, materials have hardness, crops advance through growth stages on a tick, a portal built and lit takes you to a compressed hell dimension. What changes is the presentation and the fidelity: first-person weight, stamina, physical light, real materials, readable creatures.

3. The seed is the world

Every generated thing is a pure function of the seed and a position. No generation step may depend on player visit order, on wall-clock time, or on floating-point results that differ between machines. The save file therefore stores only the difference between what the seed produced and what the player did, which keeps saves small and makes any bug reproducible from a seed and a coordinate.

4. Simulation you can read back

Light, soil moisture, soil nutrients, temperature, and structural load are all real fields the game keeps. Each is exposed to the player through something they can see: a torch changes what spawns, dry soil visibly cracks, an unsupported ceiling sags before it falls. A simulated quantity with no visible consequence does not get built.

5. This laptop at 60 fps

The RTX 4050 at 1080p is the reference target, not a minimum spec. Any feature that cannot hold 60 fps there either gets a cheaper path or gets cut. Performance is a design constraint from day one, not an optimisation pass at the end.

02

Architecture

One process, three worlds inside it. The simulation never touches a Vulkan handle and the renderer never mutates game state. That boundary is what makes multiplayer a transport swap later instead of a rewrite.

The split

SIMAuthorityOwns all game state. Fixed 20 Hz tick, matching Minecraft's tick rate so ported rules keep their feel. Runs on its own thread.
LINKMessage channelCommands in, state snapshots out. A lock-free ring buffer today; a socket when multiplayer arrives. Nothing crosses except messages.
CLIENTPresentationReads snapshots, interpolates between ticks, renders at display rate. Predicts local movement and reconciles against the authority.

Because the client already predicts and reconciles against an authority it cannot see inside, the single-player game is exercising the exact code path multiplayer will need. The cost today is roughly one extra week of work and a discipline about where state lives. The saving later is the difference between adding networking and rebuilding the game.

Entity model

A lightweight archetype ECS written in-house, roughly 600 lines. Components are stored in contiguous arrays per archetype so the sim iterates them without pointer chasing. Systems declare which components they read and which they write, and the scheduler uses those declarations to run non-conflicting systems in parallel.

The reason to write this rather than take a dependency is that the entity storage has to interoperate with the chunk streaming system, the serialisation format, and the network snapshot encoder. Three of those are custom anyway.

Memory discipline

The garbage collector is the main risk to a steady frame time in C#. Three rules avoid it. Chunk data lives in pooled arrays that are rented and returned, never allocated per use. Hot loops use struct types and Span<T> with no boxing. Anything per-frame goes through a bump allocator that resets at frame end. With those in place, server GC in background mode is measured, not assumed, in M2.

03

Seed and determinism

One 64-bit number decides an entire universe. Getting this layer exactly right is what makes every later system reproducible and debuggable.

From text to number

The player types anything. If it parses as a signed 64-bit integer, that is the seed. Otherwise the string is hashed with xxHash64 to produce one. An empty field draws from the system entropy source and is then shown to the player so they can write it down.

Stream splitting

A single seed feeding every generator would correlate them, so that ore veins would line up with rivers. Instead the world seed is split into independent named streams through SplitMix64, which is fast, has no state to carry, and decorrelates well.

ulong Stream(ulong worldSeed, string domain)
{
    ulong z = worldSeed ^ XxHash64(domain);
    z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9;
    z = (z ^ (z >> 27)) * 0x94D049BB133111EB;
    return z ^ (z >> 31);
}

// domains: "continent" "erosion" "ridge" "temperature" "humidity"
//          "cave.cheese" "cave.worm" "aquifer" "ore" "vegetation"
//          "structure" "nether.terrain" "nether.fortress" ...

Position-hashed noise, not permutation tables

All noise is gradient noise whose gradients come from hashing the integer lattice coordinate together with the stream seed. That has three consequences that matter. The world is unbounded in every direction rather than repeating at a table period. Any sample can be evaluated on any thread with no shared state and no locking. And the same coordinate always returns the same value regardless of what was generated before it.

The float determinism rule

Non-negotiable

Generation math runs in double with no fused-multiply-add and no fast-math reordering, and every generator is unit-tested against a stored golden hash of its output. Without this, the same seed produces a slightly different world on a different CPU, and the save format in §18 — which stores only player edits against a regenerated base — silently corrupts. This is the single most load-bearing invariant in the project.

Rendering uses camera-relative coordinates, so world position is subtracted from the camera in double on the CPU and everything reaching the GPU is a small float. This is what prevents the geometry jitter that appears far from the origin.

04

World generation

Eleven stages turn a seed into rock, soil, water, ore, and trees. Stages one through five are two-dimensional and cheap. Six onward are volumetric and run on the GPU where possible.

01–03Landform fieldsContinentalness, erosion, ridges. Three cheap 2D fields that decide the shape of everything.
04–05Climate & biomeTemperature and humidity, then a blended biome weight vector.
06–07Density fieldHeight becomes a 3D signed distance, gaining overhangs and arches.
08–09Caves & waterThree cave families subtracted, aquifers filled.
10–11Material & scatterStrata, ore veins, structures, vegetation.

Stages 1–3 · The three landform fields

Continentalness is very low frequency noise, domain-warped so coastlines wander instead of looking like contour lines. It runs from deep ocean through shelf and coast to inland and far inland.

Erosion is an independent field that decides how worn the land is. High erosion produces flat plains and wide valleys. Low erosion produces jagged, dramatic relief. Critically, erosion also controls how much three-dimensional character the terrain gets in stage 6, which is what makes overhangs appear in young mountains and not in old plains.

Ridges come from inverted absolute-value noise, giving sharp mountain crests and sharp valley floors rather than the rolling blobs plain noise produces.

Stages 4–5 · Climate and blended biomes

Temperature combines a broad latitude gradient, a noise field, and an altitude lapse rate of roughly 6.5 °C per kilometre, so mountains are genuinely colder than the plains beside them. Humidity is its own field, pulled up near water and pushed down in rain shadows behind ridges.

Each biome is defined as a point in the four-dimensional space of temperature, humidity, continentalness, and erosion, with a radius of influence. A position samples its distance to every biome point and produces a weight vector, not a single winner.

The blended-biome payoff

Because a position carries weights rather than one biome ID, terrain height, material choice, vegetation density, and even fog colour all interpolate across the border. There is no line in the ground where pine forest becomes desert. This single decision removes the most recognisable visual tell of block-game world generation, and it costs almost nothing because the weights are computed once per column and reused by every later stage.

Stage 6 · Height, then density

A base height is produced per column by evaluating a spline over continentalness, offset by a second spline over erosion multiplied by the ridge field. Splines are piecewise-linear control point lists stored in content files, so terrain character is tuned by editing data, not by recompiling.

That height then becomes a signed distance, which is where the terrain stops being a heightmap:

d(p) = (p.y - height(p.xz)) * verticalScale
     - noise3D(p * 0.015) * overhangStrength(erosion)
     - noise3D(p * 0.06)  * 0.35

// d < 0 is solid rock, d > 0 is open air, d == 0 is the surface.
// overhangStrength is near zero on eroded plains and large in
// young mountains, so cliffs undercut where they geologically should.

Stages 8–9 · Caves and water

Three cave families are subtracted from the density field, each doing a different job.

  • Cheese caves come from taking low-frequency noise and carving where its absolute value falls below a threshold. These produce the large open caverns worth building a base inside.
  • Spaghetti caves are two ridged noise fields intersected, producing long winding tubes roughly two to four metres across. These are the ones you follow.
  • Noodle caves are thin, high-frequency, and mostly dead ends. They exist to make the cave network feel irregular rather than designed.

Cave density is biased upward near hillsides so that entrances actually appear on the surface, which is a deliberate playability cheat over pure realism. Aquifers then assign a local water table height per region, and any cave volume below its region's table fills with water. Lava does the same below roughly −300 m. Since the terrain is an SDF, a flooded cave has a genuinely flat water surface meeting a genuinely curved rock wall.

Stage 10 · Materials and ore

Material assignment reads depth below surface, biome weights, slope, and a strata field. Slope matters: grass and soil cannot cling to a face steeper than about 40 degrees, so cliffs expose bare rock automatically with no authoring.

Ore veins are blob-shaped noise clusters gated by a depth rarity curve, following Minecraft's structure of common metals shallow and rare ones deep. The difference is that a vein is a continuous region of the material field rather than a scatter of cubes, so mining one is a matter of following the seam.

Stage 11 · Structures and vegetation

Structures are placed on a jittered grid: each cell of a coarse lattice deterministically decides whether it holds a structure and where inside the cell it sits. Placement then tests the terrain for enough flat ground. Because the test only reads the seed-derived field, it gives the same answer whether or not the player has ever been nearby.

Vegetation uses deterministic Poisson-disc scatter per chunk, with density from biome weights, humidity, and slope, and with a per-instance size and rotation drawn from the position hash. Trees are instanced meshes with procedurally varied trunk curvature rather than generated geometry, which keeps them cheap enough to render thousands of.

05

Terrain and building, the hybrid

Two systems share the world. The ground is a field you carve; structures are parts you assemble. Knowing exactly where the line falls prevents both systems from fighting.

The division

Terrain layer · SDF

Everything natural. Rock, soil, sand, ice, ore. Freely carved and freely filled at any angle with brush operations. Meshed by surface nets. This is what a pickaxe and a shovel act on.

Structure layer · parts

Everything built. Walls, beams, floors, roofs, stairs, doors, furniture. Placed as instanced meshes that snap to a socket graph. Authored geometry, so it looks like architecture rather than like sculpted mud.

The reason to split them is that these two goals are in direct conflict. Carving a field gives organic, freeform results and is exactly wrong for a straight wall with a clean corner. Snapping authored parts gives crisp architecture and is exactly wrong for a cave. Trying to serve both with one representation produces something that does neither well.

How parts snap

Each part carries typed sockets on its edges: a wall has sockets top, bottom, left, and right, each tagged with what may connect. When a part is held, the game searches nearby existing sockets of compatible type within a tolerance and previews the snapped result. Free placement without a socket is allowed on terrain, and that placement then conforms to the ground normal.

Structural integrity

Both layers feed one load simulation, which is the mechanism that ties them together and is the source of a lot of the game's tension.

  • Each part and each terrain region has a support value from 0 to 1, where a value of 1 means it is grounded.
  • Support propagates outward from bedrock and from the ground, losing strength with distance according to material. Stone carries load about three times further than wood.
  • A part below its support threshold visibly sags and creaks first, then falls a few seconds later. That warning window is what makes the system feel fair rather than punitive.
  • Mining out a cave ceiling drops the support of the rock above it. Over-mine and it collapses on you. Place timber support beams and it does not.

Design consequence worth naming

This turns mining from a resource-collection chore into an engineering problem, and it is the clearest place where the realistic world produces gameplay Minecraft cannot have. It is also a system that can make the game miserable if it is too aggressive, so the threshold ships tunable and starts forgiving.

06

Meshing, level of detail, streaming

Turning a density field into triangles fast enough to do it while the player is swinging a pickaxe. This is the hardest engineering in the project and the most likely place to lose weeks.

Surface nets with feature preservation

Standard marching cubes is rejected because it produces sliver triangles and cannot represent a sharp edge, which matters the moment a player cuts a flat floor. Instead the mesher uses dual contouring by surface nets: one vertex per cell that contains a sign change, positioned by minimising a quadratic error function built from the surface normals where the field crosses each cell edge.

The practical effect is that a natural cave wall comes out smooth and a deliberately flattened floor comes out flat with a crisp edge where it meets the wall. That single property is what lets one representation serve both a cave and a mineshaft. The QEF solve is stabilised by clamping the result inside the cell, which avoids the self-intersection this technique is known for.

The GPU meshing pipeline

// four compute dispatches per chunk, no CPU readback
1  sample     evaluate density + material into a 34³ padded volume
2  classify   flag active cells, prefix-sum to get output offsets
3  vertices   solve QEF per active cell, emit position/normal/material
4  indices    emit quads across each sign-changing edge

// output lands straight in a device-local vertex buffer.
// budget: ~0.4 ms per chunk. Edits remesh one chunk, not the world.

A CPU mesher exists alongside it, producing byte-identical output. It is slower, and it is what physics queries and the regression tests use, and it is the fallback if a driver misbehaves. Keeping the two in agreement is enforced by a test.

Level of detail

Chunks live in a sparse octree centred on the player. Each level outward doubles the voxel spacing and halves the resolution, which keeps the triangle count roughly constant per level while the covered volume grows eightfold.

Seams between levels are handled by transvoxel transition cells, which insert a thin band of specially-cased geometry along any face where resolution changes. The alternative, dropping a vertical skirt to hide the crack, is cheaper but visible on overhangs, and overhangs are a headline feature.

Streaming

A chunk moves through a strict state machine: unloaded, queued, generating, meshing, uploading, resident. Work is prioritised by distance and by whether the chunk is in front of the camera. Every stage runs on worker threads except the final GPU upload, which is batched once per frame on a transfer queue so it never stalls the graphics queue.

The player never waits on terrain: the movement code in §10 refuses to advance past the resident boundary, and in practice generation stays several hundred metres ahead of anyone on foot.

07

Materials and procedural textures

Every texture in the game is generated by code we write, not downloaded or hand-painted. A material is a small node graph that bakes to a compressed physically-based texture set.

Why generate rather than author

Three reasons, in order of weight. The world needs materials at many scales and many weathering states, and a graph produces all of them from one definition. Generated textures are seamless and tileable by construction, which hand-painting is not. And a graph is a few kilobytes of source that regenerates gigabytes of output, so the repository stays small and a material tweak is a one-line change plus a rebake.

The baker

SakritCraft.TextureForge is a separate command-line tool in the solution. It reads material graph definitions, evaluates them at 2048×2048, and writes a KTX2 texture array with BC7 for colour data and BC5 for normals. It runs at build time and caches by graph hash, so an untouched material is never rebaked.

Node vocabulary

Roughly thirty nodes cover everything needed. Generators: gradient noise, Worley cells, ridged, flow, plasma, checker, shape primitives. Transforms: domain warp, tile, rotate, scale, mirror. Combiners: add, multiply, screen, min, max, blend by mask. Filters: blur, sharpen, levels, curve, histogram normalise. Simulators: hydraulic erosion, thermal talus, dilation, distance field. Outputs: colour ramp, normal from height, curvature, ambient occlusion from height.

Applying them without visible repetition

Terrain has no UV coordinates, so materials are projected triplanar: sampled three times along the world axes and blended by the surface normal raised to a power. To kill the tiling grid that any repeated texture produces, sampling uses stochastic hex-grid blending, which offsets the lookup randomly per hexagonal region and blends three neighbours with variance-preserving weights. The cost is three texture fetches instead of one, and the result has no visible repetition at any distance.

Two further layers finish it. A macro variation texture at 64-metre scale multiplies large-scale colour drift over everything, which is what real terrain has and tiled textures never do. And runtime state layers apply wetness from rain, snow accumulation biased to upward faces, and moss biased to shaded damp ones, all computed in the shader from world state rather than stored.

08

Light, in two systems

This is the most important architectural idea in the document. Minecraft's light is a gameplay mechanic. Realistic light is a rendering problem. Trying to make one system do both is what makes realistic voxel games feel wrong. So there are two.

The dual-light design

Gameplay light is a coarse integer grid, flood-filled exactly the way Minecraft does it. It decides what spawns, what grows, and whether the player is in the dark. It is cheap, discrete, and predictable, which is precisely what makes those rules learnable.

Visual light is fully physical: ray-traced sun shadows, one-bounce global illumination, emissive materials, volumetric fog. It decides what you see and nothing else.

They are computed from the same world but never read each other. A player can learn "torches every seven metres stops spawns" as a reliable rule while still seeing light that falls off smoothly and bounces off walls.

Gameplay light

A 1-metre grid stores two values per cell, each 0 to 15, matching Minecraft exactly. Sky light propagates down from open sky, losing nothing on the way down and one level per metre sideways. Block light propagates outward from emitters, losing one level per metre in every direction. A torch at 14 therefore reaches 14 metres, which is the number players already know.

Propagation is the standard breadth-first flood fill with a removal pass, run incrementally on the simulation thread when a light is placed or removed or when terrain changes. Cells are marked passable by sampling the density field, so light correctly flows through a tunnel you carved. A cell's effective light is the maximum of block light and sky light scaled by time of day, and that number is what §14 and §12 read.

Torches matter enormously in a game about caves, so they get specific treatment: a warm point light with inverse-square falloff, a flicker curve driven by layered noise rather than a random jitter, and a colour that shifts slightly toward red as it flickers down. Lava is an emissive material feeding the same clustered light list, so a lava lake genuinely lights the cavern above it.

Exposure, and why darkness has to be dark

Eye adaptation is simulated with an asymmetric response: adapting to darkness takes several seconds, adapting to brightness takes well under one. Walking out of a lit cave into daylight briefly blows out the image. Walking in briefly blinds you. This is the single cheapest thing that makes torches feel necessary rather than decorative, and it is worth tuning carefully.

The no-ray-tracing path

Required for the integrated GPU found on this machine and for anything older than a 2018 card. Sun shadows fall back to four cascaded shadow maps with contact-hardening filtering. Global illumination falls back to the same probe grid filled by rasterised cube captures updated a few probes per frame, plus screen-space ambient occlusion. Everything downstream is identical, because the probe grid is the interface both paths write into.

09

Physics

Colliding against a field rather than against triangles, which is faster and more robust, and the reason mining can change the world every frame without rebuilding a collision mesh.

Colliding with the field directly

The terrain's collision representation is the density field itself. To test a sphere, sample the field at its centre; if the value is less than the radius, it overlaps, and the gradient of the field gives the contact normal for free. Sweeping is sphere tracing: step along the motion by the current distance value, which cannot overshoot the surface, and converge in a handful of iterations.

This is decisively better than meshing a collider. There is no collision mesh to rebuild when the player mines, so an edit is free. There is no tunnelling through thin geometry. The normal is exact rather than interpolated. And the memory cost is zero beyond the density data already resident.

The character controller

The player is a capsule 1.8 m tall and 0.3 m in radius, swept against the field and resolved by depenetration along the gradient, then by sliding the remaining motion along the contact plane. Three passes per tick handle corners. Ground is detected by a short downward probe, with a coyote-time window of 120 ms after leaving an edge so that jumps off ledges feel responsive rather than precise.

Step-up is handled by probing forward at ankle height and, if blocked, re-probing at 0.45 m and lifting the capsule if that is clear. This is what lets the player walk up rubble and stairs without jumping and without the stuttering that naive slope handling produces.

Rigid bodies

BepuPhysics 2 handles dropped items, collapsing structure parts, carts, and ragdolls. It is pure C#, so it needs no native interop and its determinism story is good. Terrain enters it as a custom collider type backed by the same sphere-tracing described above, so there is one source of truth for the world's shape.

Fluids

Water and lava are not simulated as particles, which would be both expensive and hard to control. Each body of fluid has a surface level and a volume, and flow is a cellular update on a coarse grid that redistributes volume toward lower neighbours. The rendered surface is a plane clipped against the terrain SDF with a displacement for waves. Swimming, buoyancy, and drowning read the fluid level at the player's head and chest. Breaking into a flooded cave drains it over several seconds, which is a genuinely dangerous and memorable event.

10

Movement and feel

The single most-felt system in the game. A player spends ten thousand times longer walking than crafting, so this gets tuned longer than anything else.

Stamina as the central resource

Following Skyrim's model, one bar gates sprinting, jumping, power attacks, climbing, and swimming hard. It drains at a rate per action and regenerates after a short delay once you stop spending it. Encumbrance from carried weight slows movement and slows stamina regeneration, which is what makes a mining trip a decision about what to leave behind rather than a walk back with everything.

Slopes, which matter more here than in a block game

Because terrain is continuous, slope is a continuous quantity and the game can respond to it properly. Below 35 degrees you walk normally, with a small speed penalty going up. Between 35 and 55 you begin to slide, slowly at first, and cannot gain ground. Above 55 you must climb, which costs stamina fast and fails if the stamina runs out. A scree slope has a lower friction value and slides at a shallower angle, which makes loose mountain terrain genuinely treacherous.

Mantling

Rather than the jump-repeatedly-at-a-ledge behaviour block games produce, a forward probe detects a ledge between 0.5 m and 1.4 m with clear space above it, and plays a mantle: the camera lifts along an arc while the capsule interpolates to the ledge top. It takes about 0.6 seconds and cannot be cancelled. This single animation is most of why the game will feel like a first-person RPG rather than a voxel sandbox.

Camera and weight

First person is the default, with third person available on a spring arm that collides with terrain. The first-person camera carries a small positional bob tied to footstep timing, a lag on rotation so fast turns trail slightly, and a landing dip proportional to fall speed. Each is subtle individually. Together they are the difference between a camera flying through a world and a body moving through it. All three are exposed in settings, because a meaningful number of players get motion sick from exactly this.

11

Mining

Minecraft's tier-and-hardness logic preserved exactly, applied to a field that yields real holes.

The rules, kept

Every material has a hardness, a required tool type, and a required tier. Every tool has a tier, an efficiency multiplier, and durability. If the tool type is wrong, progress is drastically slower. If the tier is too low, the material yields nothing at all, which is the gate that structures the whole progression from wood through stone, iron, and beyond.

breakTime = (hardness * 1.5) / (toolSpeed * tierMultiplier * efficiency)
          * (onGround ? 1.0 : 5.0)
          * (inWater && !aquaAffinity ? 5.0 : 1.0)

// Deliberately the same shape as Minecraft's formula, so that
// anyone who has internalised that game's pacing feels at home.

What a swing actually does

A swing raycasts against the density field. On a hit it accumulates progress at that point, shown by cracks that spread across the surface. When progress completes, a brush subtracts a sphere from the field, the affected chunk remeshes, and the removed volume converts to items.

Yield is proportional to volume removed rather than to a block count. A cubic metre of iron ore gives a fixed number of chunks of ore, so a pickaxe that carves a wider radius mines faster in every sense. Fortune-equivalent enchantments multiply the yield, not the volume.

What the field representation adds

  • Seams, not scatter. An ore vein is a continuous volume, so mining is following a seam by reading the rock, which is closer to the real activity and far more satisfying than chasing isolated cubes.
  • Tunnels with shape. A carved tunnel is round and follows the slope you swung at. Mineshafts look mined rather than extruded.
  • Consequences. Volume removed feeds the support simulation from §05, so a wide unsupported chamber sags, creaks, and eventually comes down.
  • Smoothing and filling. Placing material is the same brush operation with the sign flipped, so repairing a wall or sculpting a floor uses the same verb as mining.
12

Farming

Minecraft's till, plant, water, wait loop, with soil that is actually modelled. The extra depth all comes from three numbers per patch of ground.

Soil state

Tilling with a hoe converts terrain surface material to farmland and attaches a soil record: moisture from 0 to 1, nitrogen, phosphorus, and potassium each from 0 to 1, and a tilth value that decays as the soil is walked on and is restored by tilling again.

Moisture spreads from water sources through the soil by permeability, so an irrigation channel waters a radius that depends on whether the ground is sand or clay. Moisture evaporates faster in heat and in direct sun, and rain adds to it. Nutrients deplete as crops grow and are restored by compost, by manure, or by leaving the ground fallow.

Growth

Crops advance through discrete stages on the simulation tick, exactly as Minecraft does, but the chance to advance is the product of several factors rather than a flat probability:

growthChance = base
             * lightFactor       // gameplay light grid ≥ 9, from §08
             * moistureFactor    // peaks in a band, drowns above it
             * temperatureFactor // each crop has a preferred range
             * nutrientFactor    // limited by the scarcest nutrient
             * seasonFactor      // §16

The light threshold of 9 is taken straight from Minecraft, and it is what makes an indoor torch-lit farm work, which is a beloved mechanic worth preserving precisely.

Crop rotation, the one genuinely new idea

Different crops draw down different nutrients and some restore one. Legumes fix nitrogen. Cereals consume it heavily. Root vegetables draw phosphorus. Planting the same crop repeatedly exhausts the specific nutrient it needs and yields collapse; rotating maintains the soil indefinitely. This is a real agricultural system, it is genuinely interesting to optimise, and it costs three floats per patch of ground.

Animals

Livestock follow Minecraft's breeding loop of feed two adults to produce young, with a cooldown. What is added is pasture: grazing depletes the grass in an area, which regrows over days, so an overstocked pen starves. Animals need water within a radius and shelter in cold weather. Manure from penned animals is the main route to restoring soil nutrients, which closes the loop between the two halves of farming.

Items, crafting, progression

The spine that gives mining and farming a reason to exist.

Inventory

A weight-based inventory rather than a fixed slot count, because weight is what makes the encumbrance rule in §10 matter. Items stack by type with a per-type stack limit, and the carry limit rises with a strength attribute. Containers, and a late-game pack, extend it.

Crafting

Three routes, matching Minecraft's escalation from hand to bench to specialised station.

  • By hand for a small set of survival basics: torch, crude axe, bandage.
  • At a bench with a recipe list filtered by what you carry. Grid-shape puzzles are dropped in favour of a readable list, because shaped recipes are a memorisation tax that adds nothing here.
  • At a station for transformation that takes time and fuel: smelter, forge, alchemy table, loom, kiln. These run as a queue with real duration, so smelting is a thing you start and come back to.

14

Enemies and AI

Minecraft's spawning rules, which are load-bearing for the whole night-and-caves loop, driving creatures that behave like they belong in an RPG.

Spawning, kept faithful

The rules are deliberately close to the original, because they are what make darkness meaningful and torches valuable:

  • A candidate position must have gameplay light below the creature's threshold, which is 7 for most hostiles. This reads the grid from §08, not the rendered image.
  • It must be on a walkable surface with enough clear space above, tested against the density field.
  • It must be between 24 m and 128 m from the player, so nothing appears in view.
  • A per-region population cap limits total hostiles, and creatures beyond 128 m despawn.
  • Spawn attempts run on a fixed tick with a fixed number of tries, so the rate is predictable.

The consequence is the one that matters: lighting your base stops spawns there, and lighting a cave makes it safe. That rule is learnable, and players already know it.

Behaviour, elevated

Where Minecraft mobs walk straight at you, these run a perception model and a state machine. Perception combines a sight cone modulated by the gameplay light level at your position and by whether you are sneaking, hearing with a radius that grows when you sprint or mine, and for some creatures scent, which persists in a decaying trail so they can track where you went.

States run idle, suspicious, searching, combat, and fleeing. A creature that loses you searches your last known position and the places you might have gone, rather than instantly forgetting. Pack creatures share alert state, flank, and will not all attack at once.

Damage model

Damage carries a type: slashing, piercing, blunt, fire, frost, or shock. Armour resists each differently, so a skeleton is weak to blunt and a plated creature resists slashing. This gives weapon choice a reason to exist beyond a single damage number, and it gives the Nether a clean identity, since almost everything there is fire-immune and water becomes a weapon.

15

The Nether

A second world with its own generator, reached the way you expect, and hostile in a way that follows directly from the light rules already in place.

Getting there

Build a rectangular frame of obsidian, anywhere from 4×5 to 23×23, and light it. The portal fills with a shifting surface and activates after a short delay. Standing in it for four seconds transports you.

Coordinates compress 8 to 1, so a kilometre walked in the Nether is eight kilometres in the overworld. That is Minecraft's rule and it exists for a good reason: it turns the hell dimension into fast travel, which is what makes players willing to go there repeatedly. Linking finds the nearest existing portal within a search radius in the destination, and builds one if there is none.

Why it is hostile, mechanically

One rule does all the work

The Nether has no sky, so the gameplay sky-light value is zero everywhere. Every spawn rule in §14 then applies without modification, and hostiles spawn anywhere not lit by something you brought or by lava. Nothing special had to be written. The dimension is dangerous because the existing rule says it is, which is exactly the kind of consequence a well-chosen rule produces.

Generation

The generator is the same pipeline from §04 with different inputs. A solid ceiling at 128 m and a floor at 0. The density field is dominated by cave noise rather than by a height field, producing vast interconnected caverns instead of a surface. Lava seas fill below level 32. Biomes are ash wastes, crimson fungal forest, warped fungal forest, soul sand valley, and basalt delta, blended by the same weight system.

Fortresses generate on the jittered grid as large structures of dark brick spanning lava seas, and they are the only source of several tier-4 materials.

How it looks

Lava is the primary light source, which the ray-traced global illumination handles naturally and which the rasterised fallback approximates with emissive probes. Dense volumetric ash fog gives depth and limits sight lines. Heat shimmer distorts the air above lava. The colour grade pushes hard toward red and orange with the blue channel crushed, so returning to the overworld feels like relief. Ambient audio is a low continuous roar that never fully stops.

16

Time, weather, seasons

The clock that drives spawning, farming, and the look of every frame.

The day

A full day is 20 real minutes, matching Minecraft, split into 10 minutes of day, about 1.5 minutes each of dawn and dusk, and 7 minutes of night. The sun follows a real path with declination varying by season, so its arc and its height change through the year rather than tracing the same line daily.

Sky light in the gameplay grid scales with sun elevation, crossing the spawning threshold shortly after sunset. That is the moment the world becomes dangerous, and it is signposted by the light going amber, the fog thickening, and the ambient audio changing.

Weather

Weather is a field, not a global switch, so rain can genuinely be falling a kilometre away while you stand in sun. Fronts move across the world driven by a slow-moving noise field advected by a prevailing wind. Rain wets surfaces through the shader layer from §07, fills soil moisture, and puts out fires. Snow accumulates on upward-facing surfaces above the freezing line and melts as temperature rises. Thunderstorms darken the sky enough to let hostiles survive daylight, which is a Minecraft rule worth keeping because it makes a storm an event rather than a filter.

Seasons

Each season runs 28 in-game days. Temperature shifts, day length shifts, the snow line moves up and down the mountains, foliage colour ramps shift through the year, and crop growth rates change with the season factor from §12. Seasons are what make a farm require planning across a year instead of running as a perpetual machine, and they cost very little beyond a global phase value everything reads.

18

Persistence

Because generation is deterministic, the save file only has to remember what the player changed.

The idea

When a chunk is loaded, the generator reproduces it from the seed. The save file then applies a stored list of edits on top. A chunk the player has never touched occupies zero bytes. An explored but unmodified world of many square kilometres is a save file of a few hundred kilobytes, which is the whole payoff of the determinism rule in §03.

Layout

world/
  level.dat          seed, spawn, time, season, gamerules, version
  players/<uuid>.dat inventory, position, stats
  region/
    r.0.0.0.scr      one region = 32³ chunks = 512 m cube
  nether/region/     same structure, separate dimension
  structures.dat     placed building parts, indexed by region

A region file holds a header table of chunk offsets followed by LZ4-compressed payloads. A chunk payload stores only a sparse list of voxel deltas, the soil records, the light emitters, the entities, and the structure part instances. Writes are journalled: the new region is written beside the old and renamed on completion, so a crash mid-save cannot corrupt the world.

Versioning

Every save records the generator version. If a world generated under an older version is opened after the generator has changed, terrain outside the player's edits would silently shift. The rule is therefore that the generator version is pinned per world: an old world keeps running its original generator, and only new worlds get the new one. This costs keeping old generator code around, and it is the only honest way to avoid destroying people's worlds with an update.

19

Audio

Half the atmosphere, and the system most often deferred until it is too late to do properly.

Audio runs through OpenAL via Silk.NET with a small mixer above it. Sounds are positional with distance attenuation and occlusion tested against the density field, so a creature behind rock is muffled rather than clear.

Reverb is chosen by probing the space around the listener with a handful of rays: a tight cave gives a short dense reverb, a large cavern gives a long one, open ground gives almost none. The transition as you walk into a cave mouth is done by interpolating between the two, and it is one of the strongest signals the game has for conveying space.

Footsteps select from the material under the player, which the terrain material field already provides for free. Ambient beds change with biome, depth, and time of day. Deep underground adds occasional distant sounds with no source, which is the cheapest and most effective tension the game can produce.

Roadmap

Ordered so that each milestone proves something risky and produces something playable. Every one ends with a specific thing that either works or does not.

  • M0
    Window, device, triangle

    Mining and placing Slice

  • M4
    Light, both kinds Slice
    The gameplay light grid with incremental flood fill. Day and night cycle. Torches. Ray-traced sun shadows and the irradiance probe grid, with the rasterised fallback built at the same time, not after.

  • M7

    The entity system, spawn rules reading the gameplay light grid, perception and the state machine, the first four creatures, combat with damage types, health and stamina.

    Building and surviving

    The Nether
    The second dimension with its own generator and biomes, portals with linking and coordinate compression, Nether creatures, fortresses, tier-4 materials, and the heat-and-ash look.

    Polish, and the transport swap

An honest word on scale

This is a large project. M0 through M4 is the vertical slice and is a realistic near-term target. M6 and M7 are each substantial on their own. M8 through M10 is the content and breadth phase, which is where projects of this kind usually stall, because the engineering is finished and what remains is volume. The plan is sequenced so that there is something playable and worth showing from M3 onward, which is the best defence against that.

——

Still open

Four decisions deliberately left undecided, because none of them blocks M0 and all of them are better made with something running.

  1. Combat depth. Whether attacks are directional with blocking and parrying in the Skyrim mould, or a simpler swing-and-cooldown. This changes animation requirements enormously and is best judged once movement feels right, around M7.
  2. Magic. Whether enchanting is a stat modifier applied at a station, or a full spell system with its own progression. The tier table in §13 currently assumes the former.
  3. Art direction target. Grounded and naturalistic, or stylised and heightened. The renderer supports both; the material recipes in §07 lean naturalistic and would be retuned rather than rewritten. Decide at M5, looking at real screenshots.
  4. Third dimension. Whether anything corresponding to the End exists, and what the game's ending is, if it has one at all.
